# Abydos 0.3.1

Thirteen commits since 0.3.0, and the reason for the number is the first item:
**Shift+Tab has never worked in this terminal, and now it does.** This is also
the first release you can install with `brew`.

## Shift+Tab

**It sent the same byte as Tab.** Not a wrong sequence — the *same* one, so
nothing on the other end could tell the two keys apart. An agent's shift-tab mode
toggle, a form stepping back to the previous field, readline's
`menu-complete-backward`: each of them either went forwards or did nothing, and
none of them had any way to notice they had been handed the wrong key.

It sends `CSI Z` now, which is what the terminal was already promising. Abydos
advertises `TERM=xterm-256color`, and that terminfo entry declares `kcbt=\E[Z` —
so every curses program and every line editor had looked up "back tab", been told
those three bytes, and was waiting for them.

Reported as a regression, and it is worth saying plainly that it is not one:
`CSI Z` has never appeared in this repository, on any branch, in any commit. If
it used to work for you, something on the other side changed — the key was
ambiguous here the whole time.

The two modified-key protocols were wrong about it too, and are answered ahead of
now. Kitty's own legacy table gives Shift+Tab as `CSI Z` under the disambiguate
flag, which is the only flag implemented here, so `ESC [ 9 ; 2 u` was never
right; nor was xterm's `ESC [ 27 ; 2 ; 9 ~`. ⌃⇥ and ⌥⇥ are untouched — they
belong to the window, and a terminal that swallowed them would take away
switching panes.

## Install it with brew

```sh
brew install --cask philipparndt/abydos/abydos
brew update && brew upgrade --cask abydos     # later
```

The tap is [philipparndt/homebrew-abydos](https://github.com/philipparndt/homebrew-abydos),
and the cask in it is generated by the release rather than edited by hand: a
version, a checksum and a URL, all three taken from the image that was just
uploaded. Nothing about the app changed to make this work, and the DMG on the
releases page is the same build — this is a second way to get it, not a different
thing to get.

The app still does not update itself. There is no Sparkle in it and nothing
phones home, so brew is now the only thing that will tell you a new version
exists.

## The terminal draws on the GPU by default

`terminalGPURendering` was off "while it is new", and new is the only thing that
has changed. Both paths draw the same screen; the GPU one costs the same whether
every cell has its own colour or none do, which is exactly what a full-screen
program repainting constantly asks for.

**If you turned it off, it stays off.** This is a registered default, not a
stored value, so it reaches people who never opened the switch and nobody else.
It also makes the `vhs` bell style reachable — it is a shader the CoreGraphics
path cannot draw — without selecting it: the bell still defaults to `sound`.

## What a past session left behind

Claude Code gives each session a scratch directory. They stay useful for weeks
and were reachable only by knowing the shape of the path and a UUID. They are a
root of the project view now, beside Dependencies, one row per session and newest
first, absent entirely when there is nothing in it. From a session row down it is
ordinary file rows: they list lazily, open, walk with the arrows, and can be
revealed in Finder.

The rows also stopped offering things that make no sense for them. A session row
used to carry the whole file menu — New, Rename, Open Externally and *Move to
Trash*, which reads as an offer to delete somebody's session. It now offers the
one thing a session id is good for, `claude --resume <id>`, copied ready to paste.
The **Claude Sessions** root — the row anybody right-clicks first — had the same
problem and now reveals the directory its sessions live in.

## Debugging and git

**A refused launch says what the adapter said, when it says it.** `launch` and
`attach` were sent without their answers being read, so an adapter that refuses in
the first second was answered twenty-five seconds later by a watchdog quoting
whatever it had printed by then — usually `Building …`, the adapter clearing its
throat. The refusal is read now, and from the field the protocol means to be
shown: delve puts "Version of Delve is too old for Go version go1.27.0" in
`body.error.format` while `message` says only "Failed to launch /path".

**A branch another checkout holds opens that checkout.** `fatal: 'ui' is already
used by worktree at …` is true and useless — the branch is checked out somewhere
this program can open. There is a button on the notification now, and it raises a
window already on that checkout rather than making a second one. Which checkout
holds the branch is asked of the worktree list rather than parsed out of the error
text, because a path with a space in it cannot be read out of prose.
