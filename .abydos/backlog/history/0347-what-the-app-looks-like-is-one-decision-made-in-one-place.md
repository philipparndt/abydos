# What the app looks like is one decision, made in one place

`34c16dec9` · 2026-08-07

The editor's palette was set on the editor's page and the terminal's on the
terminal's, which is how somebody ends up with a warm amber editor beside a
deep blue terminal without ever choosing that. Both now live on an Appearance
page, first in the list, together with the zoom and the sizes — the settings
somebody opens that window to change.

The terminal follows the theme by default and can still be set to anything it
likes. That is one control rather than two: a list of palettes with "Same as
the theme" at the top says both what is being used and that it follows, where
a toggle beside a list leaves somebody wondering which of them is in charge. A
green-on-black terminal beside a light editor stays a preference and not a
mistake.

Following is the default for a new installation only. Somebody who picked
Blue two months ago keeps Blue: an upgrade that quietly repaints a terminal
they chose is a bug with a nice explanation. The difference between "chose
blue" and "never chose" is only visible before the defaults are registered,
which is where that decision is now made, once.

And there is an Abydos Light. Not the dark one inverted — amber on near-black
works because the amber is the light in the room, and the same amber on paper
is a highlighter pen. The warmth moves into the surfaces instead: unbleached
paper, dark brown ink, and the accent taken down to where it can be read,
which is roughly that pigment in shadow. The terminal has its own sixteen for
daylight, since a powerline prompt is nothing but coloured backgrounds and
white on paper is not a colour.
